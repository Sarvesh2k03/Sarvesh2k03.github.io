01

Retrieval

Grounded

Ask questions about your own documents, and get answers that show their sources or admit they don't know.

Upload PDFs or notes and ask a question in plain English. Every answer links back to the exact document and page it came from, so you can check it yourself. When the documents genuinely don't contain the answer, it says so instead of inventing something that sounds right, which is the failure that makes most AI search tools risky to trust. Try it in the demo: ask who first walked on the Moon, then switch off the Apollo document and ask again.

02

Product

Triage Desk

A customer support queue where AI sorts the tickets, and the queue keeps working when the AI doesn't.

Agents see each ticket tagged with a category, a priority and a one line summary, so the urgent ones surface first instead of being read in the order they arrived. The AI is an addition, not the foundation. If the model is slow, unavailable or returns something invalid, a built in backup classifier takes over, the ticket records which one handled it, and the panel changes colour so nobody mistakes a fallback for the real thing.

03

Pipeline

NYC 311 AI ETL

A pipeline that cleans up New York City service request data every night, using AI only where it earns its place.

Four different systems report the same 311 complaints using different column names, so the data has to be reconciled before anyone can analyse it. This pipeline does that automatically on a schedule, checks its own work with 44 quality tests, and flags suspect records rather than quietly averaging them into the results. AI resolves only the column names that cheaper methods get wrong, and the whole thing keeps running when the model is unavailable.

Each column is resolved by the cheapest tier that will commit to it: a human override, an exact match, one Claude call for the remainder, then a fuzzy fallback. Every decision is logged with the tier that made it. The reference run above was produced with no API key configured, so every model call failed to authenticate and fell through to the fallback while the pipeline completed normally. Method

How I
build

Four decisions that turn up in all three projects, in the same order. They are the reason the numbers above exist.

01

Decide what happens without the model, first.

I write the version with no model in it before I write a prompt. That's what makes the AI safe to add, and it's why I can say what the model is actually worth: I've run the system both ways.

02

Make the model commit to a shape, then check the meaning.

Every call returns structured JSON against a declared schema, validated before it touches a database, and validated for sense rather than syntax alone. A proposal naming a field that doesn't exist becomes a caught error, not a corrupted column.

03

Measure against ground truth.

"Seems accurate" isn't a result. Writing down the correct answer turns accuracy into arithmetic, which is how I know the cheap tier is 100% precise on what it commits to, and exactly which columns need a model at all.

04

Make the degradation visible, and the run reproducible.

A silent fallback is a bug wearing a feature's clothes, so the interface always says which engine answered. And every figure on this page comes from a command in a README: make backfill, npm run test:coverage, python -m grounded.evaluate.
